# 1. BIENVENUE AU HACKATHON NUXCINE 2026

Bienvenue dans le **Hackathon NuxCine 2026**.

Pendant 48 heures, vous allez travailler en équipe autour d'un défi
commun : concevoir et développer une solution de mobilité intelligente
appelée **VORA**, pensée pour répondre aux réalités du contexte
camerounais.

Le Hackathon ne consiste pas simplement à reproduire une application de
VTC existante. Votre mission est de proposer une solution
**fonctionnelle, sécurisée, intuitive, innovante et adaptée aux besoins
réels des utilisateurs**.

Vous êtes libres dans vos choix technologiques. L'objectif est de
démontrer votre capacité à analyser un problème, concevoir une solution,
travailler en équipe, développer un produit et défendre vos choix devant
un jury.

> **48 heures. Une équipe. Une idée. Une solution.**

---

# 2. LE DÉFI : VORA

## 2.1 Qu'est-ce que VORA ?

VORA est un concept d'application de mobilité intelligente destiné à
faciliter les déplacements urbains.

La solution doit permettre de mettre en relation des passagers et des
chauffeurs, de faciliter la réservation d'une course et d'améliorer
l'expérience de déplacement.

Mais VORA doit aller plus loin qu'une simple application de transport.

Votre équipe devra réfléchir aux réalités locales :

- circulation et embouteillages ;
- accessibilité des quartiers ;
- repères géographiques utilisés localement ;
- état des routes ;
- coût des transports ;
- qualité du service ;
- sécurité des passagers et des chauffeurs ;
- connectivité Internet ;
- habitudes de déplacement ;
- accessibilité aux personnes ayant des besoins spécifiques.

---

# 3. OBJECTIF DU HACKATHON

Votre objectif est de produire, dans le temps imparti, un **MVP (Minimum
Viable Product)** crédible de VORA.

Votre solution doit démontrer :

1.  une compréhension claire du problème ;
2.  une expérience utilisateur cohérente ;
3.  une conception UI/UX professionnelle ;
4.  une architecture technique réfléchie ;
5.  une application fonctionnelle ;
6.  des mécanismes de sécurité ;
7.  au moins une véritable idée d'innovation ;
8.  une bonne collaboration entre les membres de l'équipe ;
9.  une documentation permettant de comprendre et démarrer le projet.

Le jury évaluera donc autant **la qualité de la solution** que votre
capacité à expliquer **pourquoi et comment vous l'avez construite**.

# 10. SÉCURITÉ : UNE PRIORITÉ

## La sécurité est une exigence fondamentale du projet VORA.

Une application de mobilité manipule des données sensibles et met en
relation des personnes dans le monde réel.

Votre équipe doit donc intégrer une réflexion sérieuse sur la sécurité.

## 10.1 Sécurité des comptes

Prévoir notamment :

- authentification sécurisée ;
- mots de passe correctement protégés ;
- validation des données ;
- gestion des sessions ;
- contrôle des accès ;
- séparation des rôles ;
- protection des informations personnelles.

## 10.2 Sécurité des passagers

Vous pouvez prévoir :

- bouton SOS ;
- partage de course ;
- partage de position ;
- informations vérifiées sur le chauffeur ;
- identification du véhicule ;
- contact d'urgence ;
- système de signalement ;
- historique de la course ;
- détection d'anomalies.

## 10.3 Sécurité des chauffeurs

Prévoir également des mécanismes permettant de :

- signaler un passager ;
- déclencher une alerte ;
- contacter l'assistance ;
- partager la course ;
- sécuriser les informations personnelles ;
- gérer les incidents.

## 10.4 Sécurité technique

Votre application doit également prendre en compte :

- validation des entrées ;
- contrôle des permissions ;
- protection des API ;
- gestion sécurisée des clés et secrets ;
- absence de mots de passe ou clés API directement dans le dépôt ;
- gestion des variables d'environnement ;
- limitation des accès aux ressources ;
- protection contre les accès non autorisés.

> **Ne placez jamais de clés API, mots de passe, tokens privés ou
> secrets directement dans GitHub. Utilisez des variables
> d'environnement et documentez leur configuration.**

# 18. MANUEL DE DÉMARRAGE DU CODE --- OBLIGATOIRE

## Votre projet doit pouvoir être repris par une autre personne.

Vous devez donc fournir des instructions précises permettant à un membre
du jury ou à un autre développeur de lancer votre projet.

Votre documentation doit répondre clairement à la question :

> **« Je viens de cloner votre dépôt. Que dois-je faire pour lancer
> votre projet ? »**

## Exemple

```bash
git clone VOTRE_REPOSITORY
cd votre-projet
```

Puis préciser :

```bash
npm install
```

ou, selon votre technologie :

```bash
flutter pub get
```

ou :

```bash
pip install -r requirements.txt
```

ou toute autre commande nécessaire.

Ensuite préciser :

```bash
npm run dev
```

ou la commande adaptée à votre projet.

## Variables d'environnement

Si votre projet utilise des clés API ou des variables d'environnement,
fournissez un fichier :

```text
.env.example
```

Exemple :

```text
MAP_API_KEY=
DATABASE_URL=
AI_API_KEY=
```

Ne fournissez jamais vos véritables clés privées dans GitHub.

## Base de données

Si une base de données est nécessaire, expliquez :

- comment la créer ;
- comment importer les tables ;
- comment lancer les migrations ;
- comment créer les données de démonstration ;
- quels identifiants utiliser.

## Comptes de démonstration

Si nécessaire, fournissez des comptes de test :

```text

CHAUFFEUR
Email : driver@example.com
```
